# Deadlock Ruiner

Разбор матчей Deadlock в духе battlepass.ru/ruiner: 2D-реплей, хорошие и плохие моменты каждого игрока, руинометр и таблица «кто из нас больше руинит».

## Как пользоваться

```
.venv\Scripts\python ruiner.py player 229120037 -n 5   # последние 5 матчей игрока (account id или SteamID64)
.venv\Scripts\python ruiner.py match 120781425          # один матч по id
.venv\Scripts\python ruiner.py file путь\к\матчу.dem    # локальная демка (кнопка Download Replay в игре)
.venv\Scripts\python ruiner.py local                    # все новые демки из папки replays Deadlock
.venv\Scripts\python ruiner.py serve                    # открыть сайт на http://localhost:8765
```

В режиме `serve` на главной странице есть панель «Разобрать матч» (ID или ссылка на матч) и «Найти игрока» (ник в Steam, friend code, SteamID64 или ссылка на профиль). Задачи идут в очередь и разбираются по одной.

После патча обнови карту и иконки: `.venv\Scripts\python assets.py` (качает миникарту, кемпы, зиплайны и иконки героев в `web/assets`).

Друзья — в `web/friends.json` (`account_id` = friend code в Steam). Ещё их можно добавить прямо на вкладке «Друзья», но так они сохранятся только в этом браузере.

## Как устроено

- `fetch.py`: по match id берёт salts из deadlock-api.com и качает демку с replay-серверов Valve. Файл называется `.dem.bz2`, но внутри часто zstd.
- `analyze.py`: парсит демку через [boon](https://boon.readthedocs.io), ищет моменты и считает руинометр. Пишет `web/reports/<id>.json`.
- `web/index.html`: сайт целиком в одном файле: карта, таймлайн, табло, моменты, друзья.

Демки после анализа удаляются (каждая около 300 MB). Оставить можно флагом `--keep`.

## Правила моментов

| Момент | Когда срабатывает |
|---|---|
| Смерть в одиночку | при смерти в радиусе 3000 нет живых союзников, а врагов 2+ |
| Непотраченные души | на момент смерти больше max(1500, 15% net worth) |
| Отдал серию | у умершего была серия из 3+ убийств |
| Размен | команда забрала убийство в течение 8 с, штраф за смерть меньше |
| Выиграл / проиграл линию | разница душ с вражеской парой на линии к 10:00, ±1500 |
| Команда дралась без тебя | после 10:00 в тимфайте 3+ союзника, ты жив и дальше 5000 юнитов |
| Сплит-пуш | ты не в драке, но за это время нанёс 400+ урона по объектам |
| Выиграли / проиграли тимфайт | тимфайт с 4+ участниками и 2+ смертями |
| Double kill, прервал серию, соло-килл, снёс объект, донёс урну | хорошие моменты |
| Потерял урну | урну выбили по дороге |
| Слабый / отличный фарм | окно 2 минуты после 8:00: прирост душ < 45% или > 170% медианы лобби; для слабого — живой и без драк |
| Не прожал ульту | ульта была готова с начала драки, не скастована, драка проиграна или ты умер |
| Ульта решила драку | после каста команда забрала 2+ убийства за 8 с и выиграла драку |
| Умер с готовой ультой | при смерти ульта готова и не кастовалась последние 15 с |
| Слил вход в драку | первым умер в первые 5 с драки, нанеся < 12% урона команды |
| Лучший урон в драке | выигранная драка, максимум урона в команде и ≥ 30% её урона |

Касты ульты определяются по таймеру кулдауна: каст — это момент, когда время каста совпадает с текущим. Последующие сдвиги таймера — это предметы на CDR.

**Руинометр (0–100).** Для каждой метрики считается z-score внутри своей команды: души, урон в минуту, участие в убийствах, урон по объектам, линия, смерти, смерти в одиночку, пропущенные драки, время мёртвым, накопленные души, провалы фарма, смерти с готовой ультой, непрожатые ульты. Взвешенная сумма даёт оценку, 50 — средний по команде. Вердикты: ≤35 «Тащил», ≤62 «Норм», выше «Под вопросом».

## Ограничения

- Не у каждого матча есть реплей на серверах Valve. Хранятся они около 10 дней.
- Цвета и названия линий пока не сверены, линии подписаны по положению на карте: левая, центральная, правая.
- Пороги правил подобраны на глаз, их надо калибровать на ваших играх.

## Сайт

Сайт: https://dl-ruiner.github.io/deadlock-ruiner/

GitHub Actions (`.github/workflows/ruiner.yml`) каждые 3 часа разбирает новые матчи всех из `web/friends.json` и выкладывает сайт на Pages. Разборы хранятся в ветке `data`.

Разобрать конкретный матч или игрока можно так:
- открыть issue с заголовком `match <id или ссылка>` или `player <ник>` (на сайте есть кнопка);
- или Actions → ruiner → Run workflow, поле request. Пустое поле разбирает новые матчи друзей.
